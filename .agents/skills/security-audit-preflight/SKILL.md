# Codex スキルを使う準備の確認

このリポジトリの `.agents/skills/` を対象に、実際の前提を読み取りだけで確かめる。インストール・ログイン・リンクの変更は、別途頼まれたときに行う。

## 確かめる

1. このスキルからの相対パス `scripts/check.sh` を `bash` で実行する（対象プロジェクトの作業ディレクトリは変えない）。スクリプトは、各スキルの定義と呼び出し設定・リンク、Cloudflare の `security-audit` の主要ファイル、`gh` の版・ログインと `gh api` の `--paginate --slurp` 対応、監査結果の保存先に書けるかを確かめ、✅・⚠️・❌ の表で出す（すべて ✅ なら 1 行）。
2. スクリプトで確かめられない次の前提を、読み取りだけで確かめる。
   - サブエージェントを起動できるか（security-audit-sync-issues の Coordinator と元スキルの Worker が使う）。
   - 元スキルが確定に求める隔離環境（外部ネットワークを禁じた、OS で強制したサンドボックスなど）があるか。なければ「監査はできるが、確定までは進めない（要検証は Claude Code の security-audit-verify-items で確かめる）」と書く。
   - 対象プロジェクトがあれば、[登録先の決め方](../security-audit-sync-issues/references/issue-sync.md#監査開始前に登録先を特定する) でリポジトリを特定し、[登録先の確認コマンド](../security-audit-sync-issues/references/issue-sync.md#2-登録先と既存-issue-を確かめる) で非公開・Issue の有効化・アーカイブ状態を調べる。対象や書き込み権限が分からなければ未確認とする。
3. 監査・Issue の反映・テストは起動しない。推測で確認済みにせず、未導入・未ログインと権限不足を区別する。秘密値は表示しない。

## 報告する

- スクリプトの表をそのまま示し、2. の結果を、スキルごとの「使える・条件付き・使えない・未確認」と不足への対処として足す。
- リンクがないスキルは「使えない」とする（監査するプロジェクトの直下で使うため）。同名の別ファイル・別の場所への有効なリンクは置き換えず、その状態を報告する。リンクの対処には、このリポジトリの `scripts/link-skills.sh --codex` を案内する（worktree ではメインの checkout から実行する）。
- 不足への対処は、対象の OS とプロジェクトで採用された方法に合わせて案内する（スクリプトの対処方法は macOS と Homebrew での例）。
- 確認した範囲と未確認の前提を明記し、全スキルの実行成功を保証しない。
