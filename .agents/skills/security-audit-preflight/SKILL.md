# Codex スキルを使う準備の確認

このリポジトリの `.agents/skills/` を対象に、実際の前提を確認する。確認だけを行い、インストール・ログイン・リンクの変更は別途依頼された場合に行う。

## 基本環境を確認する

1. このスキルからの相対パス `scripts/check.sh` を `bash` で実行する。対象プロジェクトの作業ディレクトリは変えず、スキルの実際の配置を基準にスクリプトのパスを解決する。
2. 出力にある各スキルの `SKILL.md` と、存在する `agents/openai.yaml` を読む。定義の存在と利用可能を区別し、フォルダ名と `name`、参照する補助ファイル、呼び出し設定、必要なコマンド・外部スキル・認証を確認する。スクリプトは定義とリンクのほか、Cloudflare の `security-audit` の主要ファイルを確認する。YAML の構文や外部スキルの出所は別途確認する。
3. 実際に使うコマンドや認証だけを、存在確認・バージョン表示・ログイン状態の取得など読み取り専用の方法で確かめる。確認する項目は、各スキルの定義から決める。

## 対象プロジェクトの前提を確認する

- 対象が指定されていればその場所、なければ現在のプロジェクトの指示・README・実行設定・CI を静的に読み、利用スキルに必要な構成を確認する。対象未指定なら固有の前提は未確認とする。
- `security-audit-sync-issues` は、基本確認の結果から `~/.agents/skills/security-audit/` に定義・参照ファイル・スキーマ・両バリデーターがそろっているか確かめる。別の信頼済みの配置先が指定されていれば、そこで同じファイルを確認する。`node` とサブエージェントを使えるか、監査結果の保存先を読み書きできるかを別途確認する。
- Issue の反映に必要な `gh` の版・ログイン状態と、`gh api` が `--paginate`・`--slurp` に対応しているかを確認する。対象プロジェクトがあれば、[登録先の決め方](../security-audit-sync-issues/references/issue-sync.md#監査開始前に登録先を特定する) でリポジトリを特定する。その結果を使い、[登録先の確認コマンド](../security-audit-sync-issues/references/issue-sync.md#2-登録先と既存-issue-を確かめる) で非公開・Issue の有効化・アーカイブ状態を調べる。対象や書き込み権限が分からなければ未確認とする。ここでは定義・環境・GitHub の状態を読み取り専用で確認する。
- 事前確認は読み取り専用に限る。監査・Issue の反映・テストは起動しない。コマンドの存在・信頼済みツールの版・接続状態以外は推測で確認済みにせず、未導入・未ログインと権限不足を区別する。秘密値は表示しない。

## 結果を報告する

- 日本語で、スキルごとの「使える・条件付き・使えない・未確認」、根拠、不足と対処を表で示す。`security-audit-preflight` 自身は基本チェックが実行できれば使えると判断できる。他のスキルも、必須の前提を確かめた範囲で判断する。
- スキルは監査するプロジェクトの直下で使うので、リンクがないスキルは「使えない」とする。同名の別ファイル・別の場所への有効なリンクは置き換えず、その状態を報告する。リンクの対処には、このリポジトリの `scripts/link-skills.sh --codex` を案内する。worktree ではメインの checkout から実行する必要がある。
- 不足への対処は対象の OS・プロジェクトで採用された方法に合わせて案内する。確認した範囲と未確認の前提を明記し、基本チェックだけで全スキルの実行成功を保証しない。
